# 1. 배경 지식

- **데이터 전송 단위**:
    - **Word**: 레지스터 ↔ 메인 메모리.
    - **Block**: 메인 메모리 ↔ 보조기억장치 (가상 메모리에서 'Page'의 단위가 됨).

---

# 2. Address Binding (주소 바인딩)

프로그램이 메모리 어디에 올라갈지 결정하고, 주소를 연결하는 과정입니다.

## (1) 논리 주소 vs 물리 주소

- **Logical Address (논리 주소)**: 프로세스마다 독립적으로 가지는 0번지부터 시작하는 주소. CPU가 생성하는 주소입니다.
- **Physical Address (물리 주소)**: 실제 메모리(RAM)에 할당된 주소입니다.

![image.png](Ch%207%20%EB%A9%94%EB%AA%A8%EB%A6%AC(%EC%A3%BC%EA%B8%B0%EC%96%B5%EC%9E%A5%EC%B9%98)%20%EA%B4%80%EB%A6%AC/image.png)

## (2) 바인딩 시점 (Binding Time)

- **Compile time**: 컴파일 시점에 물리 주소 결정 (변경 불가, 비실용적).
- **Load time**: 메모리에 적재될 때 결정 (Relocatable code).
- **Execution time (Runtime)**: 실행 중에 주소가 계속 바뀔 수 있음.

---

# 3. Dynamic Loading & Swapping

- **Dynamic Loading**: 모든 루틴을 메모리에 다 올리지 않고, 호출될 때만 적재하는 방식입니다.
- **Swapping**: 메모리에 있는 프로세스 전체를 보조기억장치(Swap device)로 내보내고(Swap-out), 다시 들여오는(Swap-in) 작업입니다.

---

# 4. Continuous Memory Allocation (연속 할당)

프로세스를 메모리에 **연속된 덩어리**로 올리는 방식입니다. 이 방식의 한계 때문에 다음 장의 **비연속 할당(가상 메모리)**이 등장합니다.

## (1) Uni-programming

- 한 번에 하나의 프로세스만 실행. 가장 단순하지만 메모리 낭비와 시스템 효율이 매우 낮습니다.

## (2) Fixed Partition Multiprogramming (FPM)

![image.png](Ch%207%20%EB%A9%94%EB%AA%A8%EB%A6%AC(%EC%A3%BC%EA%B8%B0%EC%96%B5%EC%9E%A5%EC%B9%98)%20%EA%B4%80%EB%A6%AC/image%201.png)

- 메모리를 미리 고정된 크기로 나누어 둠.
- **문제점**: **Fragmentation(단편화)** 발생. (프로세스보다 칸이 커서 남는 공간이 생김)
    - Internal fragmentation
    - External fragmentation

## (3) Variable Partition Multiprogramming (VPM)

![image.png](Ch%207%20%EB%A9%94%EB%AA%A8%EB%A6%AC(%EC%A3%BC%EA%B8%B0%EC%96%B5%EC%9E%A5%EC%B9%98)%20%EA%B4%80%EB%A6%AC/image%203.png)

- 프로세스 크기에 맞게 동적으로 칸을 나눔.

- **문제점**: **External Fragmentation**
